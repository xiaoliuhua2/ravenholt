# 小程序 / APP 抓包资产的凭证长效性验证（2026-09-15 · 联通小程序实证）

> 触发：用户丢来一份抓包（Yakit / Burp / mitm）说「挖这个小程序/APP」。这是**锁面**任务，不要资产搜索出圈。
> 核心思路：**抓包里的凭证会不会过期、能不能吊销、会不会被带出到别处** —— 这三问决定有没有洞。

## 0. 流水线（一次过）

```
1) 落盘        从抓包库只读导出到 资产/flows/{id}_{method}_{sanitized_url}.txt + index.tsv
2) 建清单      按 host+path 去重 → 接口清单.md（次数/METHOD/状态码/flow id）
3) 分域        自家业务域 / 内嵌 H5 静态域 / 埋点数据域 / 第三方域
4) 鉴权矩阵    每条接口「原包重放」vs「剥离凭证（Cookie/ticket/Authorization）重放」对比长度与业务码
5) 凭证建模    找出真正的身份载体（不是 UA、不是 acw_tc 这类 WAF cookie），给它定型
6) 长效性测试  延迟重放 / 跨 UA / 无 Cookie / 多密文指纹对比
7) 泄漏扫描    凭证有没有出现在 URL query、Referer、埋点 ref、跨域上报里
8) 出报告      只写中危以上；复现步骤用整包
```

## 1. 只读导出（Yakit 库）

- 库路径从 MCP 返回里拿（`current_database`）。`?mode=ro` + `text_factory=bytes` 打开，别用 MCP 直接拉包（一条 8KB 包就能爆上下文）。
- 先只导出 `url/method/status/content_type/body_length` 做测绘，确认目标域后再全量落包。
- **★ 还原方式（2026-09-16 巨人修正 · 覆盖分期乐旧写法）：** `request`/`response` 是**整包做过一次 JSON 字符串转义**的文本。**但「转义体外面带不带引号」随 Yakit 版本不同**：
  - **Yakit 1.4.8 实测：字段值本身就带外层引号**（`repr` 出来是 `'"GET / HTTP/1.1\\r\\nHost: ...'`），此时正确写法是 **`json.loads(raw)`**，**不能再套 `'"'+raw+'"'`**（会变成 `""GET...""` → JSON 解析失败 → 走到手工兜底 → 还原出的报文**头部多一个 `"`**，报文头解析全崩）。
  - 稳妥做法 = **两个都试**：
    ```python
    for cand in (raw, '"' + raw + '"'):
        try: return json.loads(cand)
        except Exception: continue
    ```
  - 手工替换兜底必须**四趟按序**：`\r\n`→CRLF → `\n`→LF → `\"`→`"` → `\\`→`\`（漏最后一趟时，含 `\\\"` 的嵌套 JSON 会还原错）。
- **★ 正确性必须自检：拿报文头里的 `Content-Length` 对 body 的实际字节数**，逐条比对（分期乐 178/178 通过才开始挖）。这比肉眼验证可靠得多。
- **★ 写盘必须二进制**：还原后的文本用**文本模式**写（Windows）会把 `\n` 变成 `\r\n`，报文里真实的 CRLF 就变成 `\r\r\n`；下次用 `newline=""` 读出来再规范化一次就成了 `\n\n` → **报文头解析全崩**（症状：`HEADERS` 解析成空、body 里全是头）。一律 `open(..., "wb")` 写、`open(..., "rb")` 读。

## 2. 凭证定型的判据（决定性）

| 见到什么 | 是什么 | 怎么测 |
|----------|--------|--------|
| `Set-Cookie: acw_tc=...` | 阿里 WAF 会话，**不是**身份 | 忽略 |
| 每次请求都变、且与身份无关的串 | 埋点/防重放 nonce | 忽略 |
| 长度 344/684 base64、末尾 `==` | RSA-2048/4096 密文（前端公钥加密） | 重放、跨 UA、延迟重放 |
| 形如 `{9随机}{31~32hex}{7随机}` 48 字符 | 业务 ticket（网关票据） | 换票接口重放 + 拿去打业务口 |
| `microHallUser` / `TOKEN` / `microHallAccessToken` | 加密的身份 Cookie | 单独带它打业务口 |

**关键动作：同一份密文在不同时间、不同 UA、无 Cookie 下重放，都成功 ⇒ 它不是会话，是长期 bearer 凭证。**
佐证技巧：拿**多个来源**的密文调同一个换票接口，比较返回凭证的**前 40 字符指纹**。指纹相同 ⇒ 多个密文解密后是同一个 openid（说明是「每次加密不同、身份恒定」的确定性身份，不是一次性票据）。

### 2.1 ★ 鉴权载体定位法（逐项剥离 + body 注入 · 2026-09-16 分期乐实证）

抓包里有 4～5 个候选 Cookie（`session` / `www_token_id` / `uid` / `_SUTC` / WAF cookie）时，**别猜**。挑**一个敏感只读业务口**，跑这一组对照，看哪一项能复现 `uid=本人`：

| 用例 | 目的 |
|------|------|
| 全 Cookie（基线） | 确认会话与接口都还活着 |
| 只带候选 A / 只带候选 B / … | 找出**唯一有效载体**（其余单项必回登录码） |
| 全部去掉 | 拿到「未授权」的**回码基线** |
| **无 Cookie + 在 body 里注入会话标识** | ★ 最容易漏的一枪：网关常同时支持 Cookie 与 body 传参 |
| body 注入但换成随机值 | 假值对照，确认注入的不是被忽略的字段 |

- **判据**：只有某单项能复现 `uid=本人` ⇒ 那就是唯一载体；body 注入成功 ⇒ **会话标识是明文请求参数，Cookie 的 HttpOnly/SameSite/Secure 保护全部失效**（任何 session 泄漏途径直接等于接管）。
- **反向排除也很快**：改了参、回包**逐字相同（含长度）** ⇒ 该参数服务端**不消费**。分期乐一枪排掉了 `externalUserId` / `uid` / `www_token_id` / `_SUTC` 四个候选。

### 2.2 ★ 登录票据（lxCode / ticket）定性判据

抓包里出现形如「被拼进 H5 登录 URL query 的一长串 base64」的东西时，**不要**在抓包里反复重放来猜它是什么。直接做这个实验：

1. **全新客户端**（无任何 Cookie、无原 App 环境、不做前置授权）——只用**票据本身**去调**换票接口**；
2. 换出**完整登录态**（回包给出 uid + 身份 Cookie，再用新 Cookie 打业务口拿到 `is_login=1` 和本人身份数据）⇒ **它是账号级登录凭证，等价于账号密码**，不是页面跳转票据；
3. 再用**随机同长度字符串**做假值对照（必被拒），完成认钥闸。

配套必查两件事：

- **是否一次性**：同一票据第二次使用返回「已使用 / 已失效」⇒ 一次性。但**「一次性」不等于安全** —— 只要它**在首次使用前长期有效**，任何抢先使用的一方（外部小程序、日志、埋点、Referer、抓包者）就直接接管。报告里必须把这条写清楚，别被一次性误导降级。
- **是否与发起端绑定**：换票接口如果**不校验任何 Cookie / Origin / 设备指纹**，就是**任何人拿到票据即可换号**。
- **外带面**：源码里搜 `extraData`、`wx.navigateToMiniProgram`、`navigateTo({url:...+"?lxCode="})`、`statReport(... URL: ...)`。**把账号级凭证交给外部小程序（`extraData:{lxcode}`）是源码级铁证。**

## 3. 三问判洞

| 问 | 成立条件 | 定性 |
|----|----------|------|
| 会不会过期 | 抓包时间 +1h 后重放仍返回成功码 | 无时效 |
| 能不能吊销 | 换出去的票据/TOKEN 没有对应失效接口；退出登录不影响 | 不可吊销 |
| 会不会外带 | 凭证出现在 URL query / Referer / 埋点 ref / 跨域上报 | 泄漏面成立 |

三问全中 + 该凭证能打业务口出数据 ⇒ 中危起步（凭证长效且外带）；若拿到**他人**的凭证并出数 ⇒ 高危。

## 4. 泄漏扫描（容易漏的一枪）

- grep 全部 flow：`ticket=`、`openid`、`Referer:` 里带 `?ticket=`。
- **内嵌 H5 是最肥的点**：小程序把票据明文拼在 H5 URL（`.../index.html?ticket=..&ticketPhone=..&ticketChannel=..`），页面每个子资源请求的 Referer 都带出去。
- **埋点/回放 SDK 会把整条带票 URL 上报到独立域**（本案例：`playback.newbuy.chinaunicom.cn/action?ref=<带票URL>`，223 次）。别把它当成「第三方域噪声」丢掉 —— 它是凭证的第二份副本。
- 静态域加 `Referrer-Policy: no-referrer` 才是修法。

### 4.1 ★ 埋点域会整体上报「接口响应 + Cookie 值」（2026-09-16 分期乐实证 · 这条最容易被漏）

不要只在埋点**请求体里搜 URL**。亲例（2026-09-16）某小程序埋点域的 `/dataCollect/` 接口，实际把下面三样**逐条、全量、明文**送出去了：

| 上报字段 | 里面是什么 | 危害 |
|----------|-----------|------|
| `system_data.session_id`（+ `token_id`） | 被采集那次接口**响应**里的会话标识 | 该会话标识可直接当账号会话用（见 §2.1）→ 数据域里沉淀全量用户可用会话 |
| `cookie_value.{www_token_id,uid,_SUTC}` | 身份 **Cookie 的完整值**（该字段还自带 `"type":"whitelistOnly"`） | 身份 Cookie 原样外发，采集方自己标了敏感仍上报 |
| `url` / `jump_url` / `response.lxCode` | 带票据的**完整 URL**，以及**接口响应对**（`"params":{...},"response":{...}`） | 登录交换票据的第二/第三份副本 |

**扫法（必须按 body 扫，不能只按 URL 扫）：**
```python
# 对每个埋点域请求，取出 request body，逐个正则跑：
for p in (r'"session_id":"([0-9a-f]{32})"', r'"token_id":"([^"]+)"',
          r'"cookie_value":\{([^}]*)\}', r'lx[cC]ode', r'"(jump_url|url)":"([^"]+)"'):
    ...
```
**判据**：`session_id` / Cookie 值 / 票据出现在**非业务域的请求体**里，是个**值得记下的事实**（说明埋点没做脱敏），但**先别当洞**——按 §4.2 过闸，过不了就只当加固建议。

### 4.2 ★★ 外带类定级「两道闸」（2026-09-16 分期乐实证 · 防高估，务必先过再写）

**先记一句最重要的话：如果凭证是「当前用户自己的」，那么整条链必须证明「能拿到别人的」，否则不算漏洞。**

| 闸 | 问什么 | 怎么过 |
|----|--------|--------|
| **闸 0 · 跨用户** | **这串凭证是"我的"还是"别人的"？** 全程有没有一处拿到他人凭证？ | 找任何「按 id/参数取他人凭证」的接口。全链只有"我自己的凭证在自家系统里转圈" ⇒ **到此为止，不成报告** |
| **闸 1 · 凭证有效性** | 这串东西能不能单独当身份用？ | 无 Cookie 只填它打业务口，出身份/列表（＝认钥闸） |
| **闸 2 · 接收侧可达性** | **公网攻击者读得到接收侧的数据吗？** | 根路径、其他 route、swagger/actuator/api-docs、**枚举二级分发 action**、同根域兄弟子域 DNS |

- **闸 2 过 ⇒ 高危**（外部可读别家的凭证数据）。**注意闸 0 也要过**：如果上报的只是自己账号的凭证、而接收侧恰好可读，那叫「数据平台未授权访问」，得单独按那个洞打（打的是数据平台，不是埋点）。
- **只过闸 1、不过闸 2 ⇒ 不成报告**：本质是「身份鉴别信息明文离开受控边界」，属**代码审计 / 数据治理发现**，最多作为加固建议附带提一句。
- **闸 0 不过 ⇒ 直接停**。分期乐实测就是这一条被驳回：上报的是**我自己**的会话、由**我自己**的客户端、发往**自家**采集域，**全链无跨用户**；`codeLogin` 用自己 lxCode 换自己会话本来就是登录功能。
- **★ 别把「自己人能读到」当攻击面**：外带到**自家**数据采集域 ≠ 外带到攻击者手里。
- **★ 别拿推测当危害**：「所有用户都这样上报」「数据平台访问面更宽」「分析师能读」——**一条实测都没有的推测，不能写进危害**。

**闸 2 的穷尽清单（分期乐实测，30 分钟做完）**：`GET /`（是不是默认页）、同域其他 route 前缀（404 说明只挂一个）、`swagger-ui.html` / `v2-api-docs` / `actuator/health` / `robots.txt`、**body 里的二级分发字段（如 `action`）枚举查询类值**、同根域 `dc2/log/bi/report/track/data/dw/olap/kibana/grafana/monitor` 等 DNS 解析。全空 ⇒ 闸 2 不过。

**自检口诀**：写高危前先问两句 ——①「这串凭证是别人的吗？」②「一个公网攻击者照着复现步骤，第几步会卡住？」答案若是"自己的"或"卡在需要内部权限"，就不是外部漏洞。

**另附一条源码级佐证（有则写，能加强说服力，但补不了闸 0/2 的缺口）**：分期乐埋点 SDK 自带一份**「不上报名单」**（`query_site_info`/`query_site_info_list` + 两个上报接口，命中即 `return`）→ 证明团队**知道要挡但没挡全**（漏了 `getLoginData`），且对 `system_data`/`cookie_value` **无字段级脱敏**；以及采集接口**匿名可写、`uid` 客户端自填**（数据完整性问题）。

**时序注意**：检查埋点上报与凭证被消耗的先后。分期乐抓到 `getLoginData`→埋点上报→`codeLogin` 的顺序，时间差 <1s；对**不消耗**的凭证（如 `session_id`）则无此时序限制，危害更大。

## 5. 鉴权矩阵的读法

对每条接口跑「原包」和「剥凭证包」，只看三样：**HTTP 状态、响应长度、业务码**。

- 剥凭证后全部返回同一句「未获取到用户信息 / 请重新登录」⇒ 鉴权严密，**收口换面**（本案例 mxx 21 条 path 全这样）。
- 剥凭证后仍出业务 JSON（本案例 `getAccountStatus`）⇒ **未鉴权接口**，接着测参数可枚举性。
- 剥凭证后长度只差几个字节（本案例 `getConfiguration`、`languageSwitch`）⇒ 公开配置，**不算洞**。

## 6. 常见坑

- **重放 ≠ 未授权**：拿用户自己的密文/ticket 重放，出的永远是本人的数据。要写成「凭证长效 / 不可吊销 / 外带」，不要写成「越权」。
- 抓包里的 `acw_tc`、`SHAREJSESSIONID`、`ecs_cook` 全是网关噪声，剥离它们不影响复现，报告里也别当身份写。
- 手机号在**多数接口加密、个别接口明文** ⇒ 那个明文的接口就是漏配点（本案例 `getAccountStatus` vs `usersmsstate`）。
- 报告整包里的 ticket 是动态的：第 2 步的包要在描述里说明「ticket 取上一步返回的 data」。

## 7. 能拿到包就解包（PC 微信 4.x / 安卓 / iOS）

> 抓包只能看到「发出去的包」；解包能看到「全部接口 + 公钥 + 加密算法 + 票据流转点」。**别跳过这步。**

### 7.1 包在哪（PC 微信 4.x，实测）

```
%APPDATA%\Tencent\xwechat\radium\users\<userhash>\applet\packages\<appid>\<version>\__APP__.wxapkg
%APPDATA%\Tencent\xwechat\radium\users\<userhash>\applet\local\<appid>\usrmmkvstorage*\   ← 本地存储（微信加密，strings 取不到明文）
%APPDATA%\Tencent\xwechat\radium\users\<userhash>\applet\local\<appid>\usr\miniprogramLog\log1 ← 运行日志（只有 API 名，无参数）
```

- `appid` 从抓包 UA 里取：`miniProgram/<appid>`。
- 老版微信 3.x 在 `Documents\WeChat Files\Applet\<appid>\`。
- 多用户目录都翻一遍，appid 目录在**某个** userhash 下。

### 7.2 解包

```bash
python3 -m wxapkg <含 __APP__.wxapkg 的目录> <输出目录> <appid>
```

- key 由 appid 派生（PBKDF2-SHA1(appid, "saltiest", 1000)），**不需要逆向**。
- 解出后主逻辑一般在 `APP/app-service.js`（几 MB），HTML/CSS 在 `APP/app-wxss.js`、`webview.app.js`。

### 7.3 解包后立刻搜这五样

| 搜什么 | 正则/关键词 | 能拿到什么 |
|--------|-------------|-----------|
| 加密公钥 | `MIIB[A-Za-z0-9+/=]{60,}` | 能离线造密文（配合算法） |
| 加密调用 | `setPublicKey\|encrypt(` | 密文的**明文拼接方式**（如 `encrypt(token + openid)`） |
| 签名 | `hexMD5(\|md5(\|authenticator` | 硬编码盐/secret + 算法。★ 拿到后**先用零请求验算法**：抓包里同一次请求带着 `sign` + `time` + `no`，按代码里的拼装式重算，**逐字节一致**才算算法对（2026-09-21 理想：`md5(path+md5(body)+time+no+salt)` 一次命中）。**但复现成功 ≠ 服务端在用** —— 再发一发假盐，被拒才算防护存在，照过则是摆设（详见 §9.3 末条） |
| 票据流转 | `?ticket=\|navigateTo({url:.*ticket` | **票据是否被拼进 URL**（外带证据，比抓包推断硬得多） |
| 域名 | `https?://[a-z0-9.-]+\.(10010\|chinaunicom)` | 小程序带出的全部业务 host（含预发布 `*.pre` / `*.st`） |

### 7.4 判读要点

- 密文 = `RSA(token + openid)` 这类「本地凭证拼接再加密」的形态 ⇒ 密文**可离线生成**，但**能不能伪造他人**取决于 token/openid 是否可预测。实测：假 token 造的密文会被拒 ⇒ 别写成「可凭空伪造」，要写成「长效 + 不可吊销 + 明文外带」。
- 解包看到的 `navigateTo({url: "?...ticket=..."})` 是**票据外带的源码级铁证**，务必写进报告描述。
- 插件目录 `APP/__plugin__/<pluginappid>/` 里常只有 html；插件逻辑在主包 service 里。运营商一键登录（nis）类插件的签名密钥就在主包，但后端多半还要微信 `X-WECHAT-HOSTSIGN`，**过不了认钥闸就别写报告**。
- MMKV 本地存储是加密的，别指望 strings 出 token。

### 7.5 ★ Flutter 包（`libapp.so` / Dart AOT）——抽接口 + 摸闸门（2026-09-16 巨人账号管家实证）

抓到的是 **Flutter 安卓包**（包里同时有 `libflutter.so` 与 `libapp.so`，业务逻辑全在 **Dart AOT 编译的 `libapp.so`**，`classes.dex` 只有壳）时的最快路径：

```python
# 1) 直接 unzip，读 lib/<abi>/libapp.so 的 ASCII 串（Dart AOT 会保留字符串字面量）
import zipfile, re
z = zipfile.ZipFile('app.apk')
data = z.read('lib/arm64-v8a/libapp.so')          # 6~8MB，arm64 一份够
S = [s.decode() for s in re.findall(rb'[\x20-\x7e]{4,200}', data)]
# 2) 按这几类逐条 grep，比盲目 strings 快得多
```

| 抽什么 | 正则/关键词 | 拿到什么 |
|---|---|---|
| 网关根 | `https?://[a-z0-9.-]+\.<品牌>\.(com\|cn)` | 全部 API host（**HTML 上一个都看不到**） |
| 接口路径 | `^/[a-z][a-z0-9_-]*/[a-z0-9_-]+$`、`/v\d+_\d+_\d+/` | 全量 API 清单（本案 30+ 条，含 `update-password`/`update-idcard`/`login-record`） |
| 模块名 | `[a-z_/]+\.dart` | Dart 源文件名（`*_api.dart` / `algorithm.dart` / `block_cipher.dart` / `cipher_parameters.dart` → 一眼看出有签名/加解密） |
| 请求构造 | `&`+`=` 片段（`&device_id=`、`&callback=`）、`get:xxx`/`set:xxx` | 参数名线索（**AOT 里参数名常被拆散，只能捞到零星几个**） |
| 密钥 | 32/40 位 hex、`MIIB…` | 本案 **一条都没有** ⇒ 盐/算法未内联，需真逆向 |

**★ 客户端 API 的「闸门顺序」摸法（本案实证，一步一档）**：
1. `GET /common/init` → **未授权**直接给 `device_id`(32hex) + `md5_key`(6 位随机) + `PHPSESSID`；其余接口空参回 `1029 此设备需要重新初始化`。
2. 把 `device_id`+`md5_key` 当参数带上 → 错误码变成 `1005 会话失效，请重新初始化会话` ⇒ **这两个参数被服务端认了**，下一层是会话/签名。
3. 另一族（`/pre_verify/*`）空参 `2012 请求缺少版本号` → 加 `app_version=1.2.6` → `1069 请求过期，请检查手机时间！` → 加 `time=<unix秒>` → `1068 签名错误！`。
4. 此时用 `md5_key` 当盐穷举 `md5(拼装)` 常见 14 组 + 大写变体 → 全不中 ⇒ **盐在 AOT 内部，字符串表里没有**，纯黑盒到此为止（要真逆向 AOT 或上真机抓包）。

**判据**：**每补一个参数、错误码往前挪一档 = 该参数语义确认**；错误码卡在「签名错误」且常见拼装全不中 = 不要再空耗，转真机抓包（Flutter 走 HTTPS，需要 r0capture/frida 或中间人）或直接记为待逆向面。

**顺带**：`/download.php` 之类「下载页」常**未授权直出 APK**（本案 23.7MB 裸下）——先看它能不能直接拿包，能拿就别去破解 JS 下载逻辑。

## 8. 白盒接口清查（解包后必做 · 405/415 判据）

> 抓包只给「App 真跑过的接口」；解包能给你「代码里所有接口」。但**代码里有 ≠ 线上存在**（历史遗留、灰度、已下线）。必须做一轮存在性清查。

### 8.1 从解包里抽全量接口

```python
# 1) 先找地址常量（各页面的 globalData / config.js）
re.finditer(r'(\w+(?:_url|_uri|Url|Uri))\s*[:=]\s*["\']([^"\']{8,120})["\']', js)
# 2) 再按「变量 + 路径」拼接抽接口
re.finditer(r'(?:' + '|'.join(base_vars) + r')\s*\+\s*["\']([^"\']{2,90})["\']', js)
# 3) 兜底：url: xxx + "path" / url:"/path"
```
变量池要自动收（`var s = globalData.api_base_uri` 这类赋值先把变量名收进来），否则会漏。

### 8.2 状态码判据（短表 #100 的工程化）

| 回包 | 含义 | 动作 |
|------|------|------|
| **404** + 站点统一错误页 | 路径不存在 | 记「已下线」。**必须先用一个已知存在的接口做对照**，确认 404 页确实是不存在页 |
| **405** | 路径存在、HTTP 方法不对 | **可靠的存在信号** → 换 POST/GET 再打。**★ 但必须先做「不存在的路径」对照（2026-09-16 反例）**：某 CDN 回源站对**任意** POST 路径（含 `/__zzz_not_exist_98765` 与 `/`）都回 405 —— 那是 nginx 的全局行为，**不是路径存在信号**。同理另一站对任意 POST 都回 **500 空 body**。**没做对照，405/500 一律不可当存在信号用。** |
| **415** | 路径存在、Content-Type 不接受 | **存在信号** → 换成 `application/json`（同样建议配对照） |
| **200 + 业务码** | 真接口 | 进鉴权矩阵 |
| 401/403 | 存在（但**先确认不是 WAF 统一拦截页**：拦截页长度/模板会与 404 对照页一致） | 进鉴权矩阵 |
| 302 | 多为安全组/跳转兜底，**不是**存在信号 | 配对照确认 |

一次批量跑完，产出**真接口 / 已下线**两张清单，落 `资产/接口清单.md` 附录。这一步能把「80 个代码接口」收敛成「十几个真接口」，避免逐个深挖浪费时间。

### 8.2.1 ★ 另一类网关：不用 HTTP 状态码，用**业务码**判存在性（2026-09-21 理想网关 `LiFE` 实证）

有些自研网关把「路径不存在」与「无权限」收敛成**同一个 `200` + 业务码**，上表的 405/415 压根不出现。这时改看**业务码分层**：

| 返回 | 含义 |
|---|---|
| `100012 没有接口访问权限` | **网关层拒绝**。★ 注意：**随便编一个不存在的路径也回这句** —— 所以它**不能**当存在信号（这就是本网关的「全局兜底」，等价于别人的 nginx 405） |
| `100002 缺少必要的请求参数: xxx` | ★★ **网关放行、到达业务层参数校验 ⇒ 路径存在**（且直接告诉你缺哪个字段） |
| `240225 Session expired` / `401 ILLEGAL_LOGIN_STATUS` | ★ 到达登录校验 ⇒ 路径存在 |
| `100033 验证IDAAS值失败，缺少鉴权参数` | ★ 到达 IDAAS 层 ⇒ 路径存在（同一集团另一端小程序走 IDAAS 鉴权） |
| Spring `100001 Required String parameter 'x' is not present` | ★ 到达框架层 ⇒ 路径存在，还顺带漏了框架指纹 |
| `100002 缺少必要的请求参数: X-CHJ-Token` | ★ 路径存在，且**要求的是请求头而不是 body 字段** |

**判据一句话**：**「不是网关那句 `100012`」= 路径存在**，而且它顺带告诉你卡在哪一层（参数 / 登录 / IDAAS / 框架）。
**必做对照**：先各打一个「已知存在」和「乱编的不存在」路径，确认乱编的确实回 `100012`、存在的回别的 —— **没做对照，整套判据不成立**（与上表 405 的坑同源）。

### 8.3 摸参最省力的姿势

对每个真接口先发**空包**（`{}` / `?`），读它的错误文案：
- `{"msg":"code不能为空"}` → 知道要哪个字段
- `{"respmsg":"登录验证失败，请重新登录！"}` → 走「长效密文」鉴权（有密文就能打）
- `{"dsc":"参数异常，请稍后重试"}` → 参数格式问题，换 JSON/form
- 直接吐业务数据 → **未鉴权接口**，进 §2 的三问

### 8.4 只吃「明文手机号 + 微信 code」的接口怎么判

小程序里常见 `data:{aucode: wx.login 的 code, mobile: 明文手机号}`。**判越权的正确姿势**：
1. 读代码确认只吃这两个参数（没有 openId 密文、没有 token）；
2. 实测**本人号 vs 对照号**，看回包是否一致；
3. 回包一致且都是登录闸 → 服务端校验了有效微信 code（一次性、微信侧绑定用户）→ **证伪，收口**，别硬磨；
4. 只有在「换号后回包明显不同 / 出数据」时才是越权。

**坑：** 405 → 用 form 发会得 415，说明服务端要 JSON；小程序 `wx.request` 默认 form，但常全局设了 JSON 头，别照抄 `data:{...}` 就以为是 form。

### 8.5 无鉴权但只发一次性令牌的接口，别报

例：`getComplaintParam` 空包返回 `{"code":"0000","data":"<每次变化的加密串>"}`。连打三次确认值每次都变（一次性 session），且该接口在业务里只服务于「自己提交自己的投诉」→ 无越权面 → **不写报告**，只登记。

## 9. 敏感信息 / 密钥专项扫描（用户常直接问「有没有 key 泄漏」）

三件事一起做，缺一个都会被问住：**包内 pattern 扫描**、**抓包响应 PII 扫描**、**线上敏感文件探测**。

### 9.1 扫什么 pattern

```
私钥PEM / RSA私钥体 / 阿里云LTAI / 腾讯云AKID / AWS AKIA / OSS密钥对 /
appSecret / password / jdbc·mysql·redis DSN / 内网IP(10.|172.16-31|192.168) /
aesKey·secretKey·signKey·salt·iv / 32位hex / 身份证 / 银行卡 / 邮箱 /
token·apiKey / sourceMappingURL
```

### 9.2 必踩的四个误报坑（不排掉就会误报一整天）

| 看着像 | 实际是什么 | 怎么确认 |
|--------|-----------|----------|
| `-----BEGIN RSA PRIVATE KEY-----` | **JSEncrypt 库源码**里 `getPrivateKey()` 拼 PEM 头尾的字符串常量 | 看标记**之后**的字符：若是 `";return(t+=e.wordwrap(this.getPrivateBaseKeyB64())…` 就是库代码；真私钥后面跟 base64 体 |
| 响应里几百个明文手机号 | **业务公开数据**：靓号库（`zopGoodNumberQuery` 的 `phone`+`featureName:"情侣靓号"`）、营业厅电话（`queryNearHallByAddress` 的 `linkMobile`） | 看字段名与同层字段（有 `hallName/hallAddress` 就是门店）；**必看上下文再下结论** |
| 「家庭地址」 | 营业厅地址（`hallAddress`） | 同上 |
| 19 位 `62` 开头数字 / 11 位 `17x` 数字 | 响应头 `EO-LOG-UUID`、`yhlocal` 哈希片段 | 定位到报文头部 |
| `credential` / `custName` / `idCard` 字段名 | JS 里的 `credentials:"include"`、空字符串 `""`、空数组 `[]` | 打印该字段的值，别只看键名 |

### 9.3 认钥闸（不过闸就别写报告）

抄到密钥 ≠ 洞。必须**假值对照生产认了** + **认钥枪带出身份或列表**。典型不过闸的情形：
- 埋点 SDK token：能调采集接口但只回采样配置 → 带不出身份/列表 → 不写
- 运营商一键登录（nis）签名密钥：后端还要微信 `X-WECHAT-HOSTSIGN`（客户端签名，无法伪造）→ 无法生产验证 → 不写，只登记
- **弱长度 RSA 公钥**（如 512 位）：`MFwwDQYJKoZIhvcNAQEBBQAD…` 开头 = 512 bit。可先查 `http://factordb.com/api?query=<n十进制>`：`status:"C"` = 未分解；`"FF"` = 已分解可直接拿因子。**未分解且没拿到密文链路 → 属加固项，不写漏洞报告**
- 前端**会话级**加密密钥（每次请求随机 AES + RSA 传 `encrypt-key` 头）→ 机制正确，无洞
- ★ **前端签名盐 / 防刷密钥（2026-09-21 理想 `chj-x-sign` 实证 · 双向坑）**：
  - **正向**：抄到盐 + 离线复现签名，**不等于**服务端在校验 —— 必须再打一发**假值**（如把盐末位改掉）看是否被拒。
  - **反向**：若**假值也照过**（理想实测：假盐 + 真手机号打 `/mall-api/v1-0/passports/mobile/send` → `200` 且 `errors:null`），说明服务端**压根没校验**该机制
    ⇒ 不是「防护被绕过」，是**前端摆设** ⇒ **无洞、不写**。别把它写成"签名可伪造 ⇒ 绕过防刷"（那会把一个不存在的防护当被攻破）。
  - 判据一句话：**假值被拒 ⇒ 防护存在；假值照过 ⇒ 防护不存在**。两者都不能只凭代码推断。
- ★ **变体：多层闸门里只坏一层（2026-09-21 理想 `X-CHJ-Token` 实证）**：
  `100002 缺少必要的请求参数: X-CHJ-Token` → 填**假值/`null`/全 0 也放行** → 进下一层 `240011 deviceId不能为空` → 补 `X-CHJ-Deviceid`（真值假值都一样）→ 进 `240225 账号登录已过期` **被拦住**。
  ⇒ **单层形同虚设、但后续层兜底、没带出任何数据** ⇒ 按 `03` 属**半条链**，**只作加固项留痕，不得写成「鉴权绕过」**。
  ⇒ 判读要点：**逐层推进时，要一直推到「被真正拦住」为止**，才能回答「这一层坏了有没有后果」；停在中间就下结论会把加固项误报成漏洞。
  ⇒ 同时也别浪费：这类「唯一功能性校验位」若后层被误配就整体敞开，值得在加固建议里点名。

### 9.4 线上敏感文件探测

```
/robots.txt /.git/config /.env /config.js /env.js /swagger-ui.html
/v2/api-docs /v3/api-docs /actuator/env /actuator/health
<每个 .js 的 .js.map>
```
- 404 = 不存在；**405 + 统一拦截页 = WAF 拦了敏感路径**（不是暴露）；200 + 内容才是发现。

## 10. 小程序/APP 接口的注入测试（怎么做差分才可信）

### 10.1 先建对照组（最重要的一步）
同一请求**连打 3 次**，比「状态码 + 长度 + 业务码 + **内容指纹**（md5(json.dumps(data,sort_keys=True))）」。
三次一致 ⇒ 响应确定性，差分可信；三次漂移 ⇒ 任何长度变化都不能当证据。

### 10.2 三条决定性判据

| 判据 | 说明 |
|------|------|
| **payload 与随机字符串返回相同结果** | `ch'`、`ch'||'1`、`ch--`、`zzzzz`、`CH` 全部返回同一指纹 ⇒ 参数**未进入查询逻辑**，非注入（本轮 `channel` 就是这样排除的） |
| **合法值也被拒** | 数字参 `0`/`-1`/`99999999` 与 `1-0`/`1*1` 同样被拒 ⇒ **参数白名单校验**，不是 SQL 算术 |
| **应用层报错 ≠ SQL 报错** | `java.lang.Long cannot be cast to java.lang.String` 是**类型转换**（参数化特征）；SQL 报错会是 `SQLException`/`ORA-`/`You have an error in your SQL syntax` |

### 10.3 小程序特有的三条"注入面"误区

- **密文参数不是注入面**：`openid` 之类是 RSA/AES 密文，服务端先解密——塞 payload 只会解密失败。别在这上面浪费轮次。
- **手机号/身份证类参数通常先过正则**：`17602803229'` 直接返回"请填写正确的手机号"就说明被格式校验拦住，不用再试变形。
- **枚举参数走白名单**：`scene=phoneBill'`、`node_code=A02'` 与随机值返回同一结果 ⇒ 白名单。

### 10.4 WAF 关键词拦截的读法
阿里云 WAF 拦 SQL 特征会返回 **405 + `data-spm="a3c0"` 的 HTML 页（约 2657B）**。
实测 `AND`/`OR`/`SLEEP` 用 `/**/`、`%20`、大小写替代空格**照样被拦** ⇒ 它是关键词识别，不是空格模式。
遇到这种拦截不要急着上编码绕过，**先确认参数是否真的进了查询逻辑**（10.2 第一条），很多情况是白干。
