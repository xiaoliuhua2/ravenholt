# WAF 绕过策略选择前置检查单（先问三问，再选技术）

> 来源：2026-09-15 陕西电信实战 + 文献核实。回答「该用哪类 WAF 绕过技术」前**必须**先过的三问。
> 核心原则：**WAF 绕过 ≠ 注入存在**。所有变异技术都是"语义等价变换"——前提是 payload 能到达 SQL 执行点。
> 执行点不存在时，换衣服没有意义。

---

## 一、三问（按顺序问，任何一问为否即止损）

### 问 1：参数真的进 SQL 吗？
判据（两个独立判据一致才下结论）：
- **算术不等价**：`x*0`（SQL 求值 → 0 → 结果必变；归一化 → 仍 x → 结果不变）
- **计时**：`x-sleep(3)`（SQL → +N 秒；归一化 → 无延时）

实例（sn.189.cn）：`290*0`≡`290-290`≡`290`（结果一字不差）、`290-sleep(3)` t=0.12s 无延时
⇒ **参数不进 SQL** ⇒ 所有 WAF 绕过技术**全部无适用面**，收工。

### 问 2：过滤在哪一层？
探法：
- `\uXXXX` 转义是否被拦 → 拦 = **JSON 解析后**（解析差异类技术被消掉）
  - ⚠️ **但「被拦」≠ 无解（2026-09-19 修正）**：这只说明 WAF **会解标准转义**。
    下一步应是 **`waf-bypass.md` §2.1b —— 去读后端解析器自己的解码实现，找它比 WAF 宽容的点**。
    亲例：fastjson 标准 `\u0040`/`\x40` 被腾讯云 WAF 拦，但 `\x4Jtype`（`digits[]` 未占位即 0）、
    `\u００４０type`（`Character.digit` 认全角数字）**全部通过**。
  - ★ 教训：**判「过滤层级」判对了，也可能因为漏了「宽容解码」这一整类而得错结论。**
- 重复键 `{"a":1,"a":2}` → 过滤器与业务取的键是否不同（有视图差 = 解析器差异可利用）
- 改 Content-Type / 编码 → 拦截行为是否变化（定位传输层 vs 应用层）

### 问 3：WAF 是规则型还是 ML 型？
- **规则型**（小词表/正则）：**测绘规则边界**（哪些拦哪些放）> 生成海量变体。
  文献实测背书：LLM 生成 payload 对规则型 WAF（ModSecurity/Coraza）绕过率仅 **0–5.7%**。
- **ML 型**（WAF Brain / CNN-WAF / 云 WAF 智能模式）：生成式对抗样本有效（文献实测最高 92%）。

## 二、技术 × 适用条件对照表

| 技术 | 适用前提 | 出处（已核实） |
|---|---|---|
| ★★ **框架宽容解码**（`\x4Jtype`/全角 `\u００４０` 等） | 被拦的是**框架特征字面量**（`@type`/`$ref`/OGNL/SpEL…）；**后端解析器比 WAF 宽容** | **实测**：2026-09-19 腾讯云 WAF + fastjson，5 种变体通过（`waf-bypass.md` §2.1b） |
| 语法树等价变异（编码、注释扩展、引号编码） | 参数进 SQL + WAF 在检测层拦截 | AdvSQLi, arXiv:2401.02615, IEEE TIFS 2024 |
| 收敛因子引导 CFG 生成 + 15 种变异 | 同上；黑盒可观察 allow/block | BWAFSQLi, DOI:10.1145/3788286, ACM TOSEM 2026-01-19 |
| LLM 生成对抗样本（RADAGAS/RefleXQLi） | **ML 型 WAF**；规则型无效 | 同上 arXiv（240 实验/240 万 payload/220 万测试） |
| 解析器差异（JSON 嵌套、重复键、NUL、编码差） | 过滤与业务**用了不同解析器**且存在视图差 | 实测：先做问 2 定层 |
| 结构包裹（数组/对象） | **业务层认该类型**（不认 = 死路） | 实测：sn.189.cn 业务层 500 |
| 协议滥用（HTTP/2、分块传输） | WAF 在传输层且与后端协议解析不一致 | 少见；先确认问 2 |
| Unicode 归一化（全角→半角） | 后端做 NFKC（**Java/MySQL 默认不做**） | 实测：全角引号放行但无害 |
| PDO 模拟预处理绕过（CVE-2025-32429） | **PHP** + PDO 模拟模式 | 技术栈不符（Java 站不适用） |

## 三、实证记录（sn.189.cn，2026-09-15）

三问答案：①参数不进 SQL（290*0≡290、sleep 零延时）②过滤在 JSON 解析后（`\u0027` 被拦）③规则型（词表：`'` `%` `or` `and` `union` `select` `order by`）。
⇒ 结论：**全部变异类技术无适用面**。实测 49 枪（37 批量 + 7 计时 + 5 Unicode）穷尽，无注入。
