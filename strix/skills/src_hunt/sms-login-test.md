# 短信验证码登录口的真机验证法

适用：目标是「手机号 + 短信验证码」登录（无密码），你想判断能不能爆、能不能绕。
**光靠假号打错码永远测不准**，必须真机收一次码，一次就能定死 5 个结论。

## 一、前置：图形验证码那一关

- 先把图形码接口找出来（前端 JS 里 `verifyCode`/`captcha`/`getVerifyCode`），看它返回什么：
  base64 图 / 是否按 phone 维度存 / 是否依赖 Cookie。
- 人工（多模态）读图填进去触发 `sendSmsCode`。读图这一步别省，
  **盲猜成功不等于有洞**——先拿假号做对照：连打 3 个明显错值（ZZZZ/1234/0000），
  全部回「图片验证码不正确」才说明校验生效。否则先怀疑自己的输入，别急着报绕过。
- 注意 WAF：连续 10+ 请求常触发频控（嘀嗒是 624 Request Deny），
  会把「错值也被拦截」误判成「校验被绕过」。频控和校验的区分标志是：**频控对所有参数一视同仁**。

## 二、真机收一次码，一次拿 5 个结论

拿到真实短信码后，按这个顺序打（每条间隔 ≥1.5s）：

1. **位数** → 4 位还是 6 位，直接决定爆破量级（4 位=1万，6 位=100万）。
2. **同号重放** → 同一码连打 2~3 次，看是否仍有效（未一次性失效 = 可重放）。
3. **跨号复用** → 同码 + 另一个手机号，回「验证码错误」才算**绑定 phone**（安全）。
   这是最关键的一条，过了就说明不能用 A 的码登 B。
4. **注册状态判定码** → 码正确但号未注册时，很多系统会回一个**专属码**
   （嘀嗒企业版是 `2005 该手机号没有注册`）。记下它，它是判断"号是否注册"的精确信号。
   但要确认**错码优先回验证码错误**，否则就是未授权注册状态枚举（那才是洞）。
5. **爆破可行性** → 位数 × 失败锁定 × 频控，三项一起算：
   6 位 + 无锁定 + WAF IP 频控 = **不可行**（100 万次请求会被频控打到死），
   这种「无失败锁定」只能算低危，别当成可爆来报。

## 三、登录口参数校验的免费差分

不带任何参数打登录口，看回什么：

```
/login/login（空参） -> {"code":102,"message":"phone参数错误"}
```

这类"参数错误"码是**免费的类型/存在性差分**，可以顺着测参数类型、边界、数组传参。
但注意：网关白名单类系统里，猜不存在的路由会统一回 403/401，**那是不能用来枚举路由的**
（能区分才叫 oracle，统一回包不叫）。

## 四、红线

- 发短信给用户自己的号是OK的；**别对陌生号码群发**（短信轰炸+资损）。
- 多数系统有 1 条/分钟频控，触发了就等，别换号绕。
- 拿到会话后**禁止调 logout/注销**；越权一律用读差分证明，不写、不批量。

## 五、进不去号怎么办

如果测试号都没注册，别灰心，先找注册口参数（前端 `registerUser` 方法里的 params 装配），
通常只需「手机号+图形码+短信码+名称」就能提交——**但注册是往生产库写数据**，
且会占用用户真实手机号，必须**先问过用户**再执行，别自作主张。
